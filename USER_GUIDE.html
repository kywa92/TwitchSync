1. What TwitchSync is

TwitchSync is a small web app that runs entirely on your own computer. It plays the Twitch VODs you have downloaded with TwitchDownloader and shows the stream’s chat beside the video, exactly the way it looked live — colored usernames, subscriber badges, emotes (including animated ones) — and keeps the two perfectly in sync. Whatever moment of the stream you scrub to, the chat column instantly shows what chat was saying at that moment.

The point of the project is to avoid re-encoding. The usual way to get chat next to gameplay in one place is to render the chat to a video and composite the two into a single new file — hours of CPU time and another enormous file per VOD. TwitchSync skips all of that: the gameplay MP4 is played as-is, and the chat is drawn live from the chat JSON, driven by the video’s clock. Nothing is converted, nothing is written, and your files are never modified.

Because chat is real text rather than a second video, you also get things a rendered chat can never give you: razor-sharp text at any window size, selectable/copyable messages, instant response to seeking with zero drift, and a chat-activity graph on the seek bar that shows you where the hype happened.

2. Requirements

  • Python 3.7 or newer. Nothing else — no packages to install, no build step. macOS includes python3 once the developer tools are present; it is also a plain installer on python.org.
  • A modern browser — Chrome, Edge, Brave, Firefox, or Safari. The gameplay files TwitchDownloader produces are H.264/AAC MP4s, which every current browser plays natively.
  • VOD files from TwitchDownloader, described in Adding new VODs. Each VOD needs its main .mp4 and its chat .json (with embedded images, which is TwitchDownloader’s common setup — see the note in that section).

There is no minimum hardware beyond “can play the video in a browser.” The app itself is extremely light; the only briefly heavy moment is parsing the chat file when a VOD opens (a few seconds for a ~90 MB chat log).

3. Quick start

  1. Open Terminal in the TwitchSync folder (the folder containing server.py and your VOD files).
  2. Run: 
    python3 server.py
  3. Your browser opens http://127.0.0.1:8710/ automatically. Click a VOD on the library page and start watching. That’s it.

Leave the Terminal window open while you watch — it is the server. When you’re done, press Ctrl+C in that window to stop it.

4. Starting the server & options

The server’s job is to hand the browser three things: the app itself, the video (streamed in ranges, so seeking a 24 GB file is instant and never downloads more than you watch), and the chat data. It listens only on your own machine (127.0.0.1) — nothing is ever reachable from your network or the internet.

Command-line options

OptionDefaultWhat it does
--dir PATH the folder server.py is in Changes the always-present library folder. You normally don’t need this — extra folders (a NAS, an external drive) are better added from the app itself, see Library folders.
--port N 8710 Listen on a different port. Use this if 8710 is taken (the server tells you if it is).
--no-open off Don’t auto-open the browser on startup. The URL is still printed so you can open it yourself.

Examples

# serve the VODs sitting next to server.py (the normal case)
python3 server.py

# VOD library on an external drive
python3 server.py --dir "/Volumes/Archive/Twitch VODs"

# different port, and don't open a browser
python3 server.py --port 9000 --no-open

On startup the server prints the folder it is serving and the URL. While running, it logs very little on purpose — one line per library refresh, plus any errors. Video streaming produces no log noise even while you scrub heavily.

Tip

Bookmark http://127.0.0.1:8710/. As long as the server is running, that link is your VOD library.

5. The library page

The first page you see is the library: one card per VOD found across all of your library folders. Each card shows the stream title (read from the chat file — the real title, not the filename), and a detail line with the streamer, the game, the duration, the file size, and the file’s date. Cards are sorted newest-first by file date. When you have more than one library folder, each card also carries a small tag showing which folder (and subfolder) the VOD lives in.

Clicking a card opens the player. The URL changes to /?v=<video name>, which means each VOD has its own address — you can bookmark a specific VOD, reload mid-watch, or use the browser’s back/forward buttons to hop between the library and the player like any normal website.

The library rescans the folder every time you visit it. Drop a new VOD into the folder, click back to the library (or reload), and it appears. No restart needed.

What counts as a VOD

A VOD appears in the library when both of these files exist in the folder, sharing the same name (the “stem”):

  • Some Stream Title.mp4 — the gameplay video
  • Some Stream Title.json — the chat log

Extensions are matched case-insensitively, so .json, .Json, and .JSON all pair correctly (TwitchDownloader has emitted more than one casing over the years). Any .mp4 with  - CHAT in its name is deliberately ignored — that’s TwitchDownloader’s rendered chat video, which TwitchSync doesn’t need (see FAQ about deleting them). An .mp4 with no matching chat file is also skipped, since there would be no chat to show.

Library folders (adding a NAS or external drive)

The project folder — the one holding server.py — is always part of your library, so dropping files next to the app keeps working exactly as before. Beyond that you can point TwitchSync at any number of other folders, and everything is listed together in one library.

Click Folders in the library header to open the manager. It lists every library folder with its full path and how many VODs it currently holds, and lets you add or remove folders. Your choices are remembered in folders.json next to server.py, so they survive restarts.

To add a NAS share:

  1. Mount the share in Finder first — Go → Connect to Server (⌘K), enter e.g. smb://yournas.local, and pick the share. macOS keeps the credentials in your Keychain and mounts it under /Volumes/. TwitchSync never handles your NAS password; it just reads the mounted folder.
  2. Open Folders in TwitchSync. Any mounted volume appears as a clickable chip below the input — click one to start the path, then finish typing the folder that holds your VODs (for example /Volumes/SHARE1821/VODs).
  3. Click Add folder. It reports how many VODs it found straight away.

Subfolders are scanned too, up to four levels deep, so a folder containing per-stream subfolders works fine. Hidden folders and NAS housekeeping directories (@eaDir, #recycle, #snapshot) are skipped — deleted VODs sitting in your NAS recycle bin won’t clutter the library.

Removing a folder (the × button) only takes it out of the library list — your files are never touched. The project folder has no × because it’s permanent. If a folder is unavailable when the app looks — the NAS isn’t mounted, the drive is unplugged — it’s shown as not mounted and simply skipped; everything else still works, and it reappears on its own once the share is back.

Performance over the network

Streaming works well over a fast LAN: the player only fetches the byte ranges it needs, so a 6-hour 1080p60 VOD pulls roughly 1 MB/s while playing — a rounding error on gigabit, let alone 2.5GbE. Seeking stays quick because only a small window around the new position is read. The one moment you’ll notice the network is when a VOD opens, since the chat log (tens of MB) is fetched in full — a second or two on a fast link.

6. Adding new VODs

TwitchSync is built around TwitchDownloader’s output. For each stream you want in the library:

  1. Download the VOD video with TwitchDownloader (its default MP4/H.264 output is exactly right).
  2. Download the chat as JSON for the same VOD, with image embedding enabled:
    • In the TwitchDownloader GUI: chat download → format JSON, and check “Embed Images” (this stores the emotes and badges inside the file).
    • With the CLI: TwitchDownloaderCLI chatdownload --id <vod id> -o chat.json -E (-E / --embed-images).
  3. Give both files the same name (identical except for the extension) and drop them into the project folder — or into any folder you’ve added, such as a folder on your NAS (see Library folders).
  4. Visit or reload the library — the VOD is there.

Important

The chat file must be plain .json — not the compressed .json.gz variant, and not the HTML or text chat formats. And it should have embedded images: without them the messages, colors, and badges’ layout still work, but emotes appear as their text names (LUL instead of the image). Already have a JSON without images? TwitchDownloader can retrofit them: TwitchDownloaderCLI chatupdate -i chat.json -o chat.json --embed-missing.

Tip

If you also rendered chat videos (… - CHAT.mp4) in the past, you can keep them in the folder — they are ignored and never played. You can also delete them to reclaim space; TwitchSync only ever uses the main video and the JSON.

7. A tour of the player

The player fills the browser window with three regions, matching how you’d watch live on Twitch:

1
2
3
3:00:15 / 13:01:18
  • 1Video stage. The gameplay video, letterboxed on black so nothing is ever cropped. Click it to play/pause; double-click it for fullscreen.
  • 2Chat column. The stream’s chat, rendered live from the log and always showing the messages for the current video time. The ‹ button in its header returns to the library.
  • 3Control bar. One set of controls for everything, spanning the full window: play/pause, elapsed / total time, the seek bar with the chat-activity graph, playback speed, volume, and fullscreen.

There is deliberately just one set of controls. You never manage the video and the chat separately — the chat has no play button and no scrubber because it simply follows the video wherever it goes.

8. Playback controls in detail

The seek bar

  • 1Chat-activity graph. Messages per minute across the whole VOD. Tall spikes are the moments chat went wild — usually the clips worth seeing. The scale caps itself so one enormous spike doesn’t flatten the rest.
  • 2Played. The purple fill is how far you are into the VOD.
  • 3Buffered. The lighter stretch past the playhead is what the browser has downloaded ahead.
  • 4Handle. Appears when you hover or drag. Drag it (or click anywhere on the bar) to seek.
  • 5Time tooltip. Hover anywhere over the bar to preview the timestamp at that position before committing to a jump.

Clicking the bar jumps straight to that point. Dragging shows a live preview — the handle, fill, tooltip, and the time readout all follow your pointer — and the video performs the seek when you release. That’s intentional: these files are tens of gigabytes, and seeking once on release is what makes scrubbing feel instant instead of stuttery. The chat follows every seek automatically.

After a big jump you may see a spinner for a moment while the browser fetches video data around the new position — normal for very large files, and usually gone in a second or two.

The buttons row

ControlBehavior
Play / pauseToggles playback. The icon reflects the current state. Clicking the video itself does the same thing.
Time readoutelapsed / total, e.g. 3:00:15 / 6:47:26. Uses H:MM:SS whenever the VOD is an hour or longer. While you drag the seek bar it previews the target time.
Speed (1×)Opens a menu: 0.25× — 2× with “Normal” = 1×. Your choice is remembered for future sessions. Audio stays pitch-corrected (a browser feature), so voices sound natural at 1.25–1.5×.

While playing in fullscreen the controls fade out after 3 seconds of no mouse movement (and the cursor hides); move the mouse or press any shortcut to bring them back. F or Esc exits.

10. The chat column

Loading

When a VOD opens, the video starts immediately while the chat column loads its data in parallel — first “Downloading chat…” with a percentage, then “Preparing emotes…” while the log is parsed and the embedded emote/badge images are unpacked. For a very long stream (tens of thousands of messages, ~90 MB of log) this takes a few seconds; shorter streams are near-instant. If the chat file is missing or unreadable, the column says “Chat unavailable” and the video keeps playing normally.

What a message shows

  • Timestamp — the VOD time the message was sent (3:00:15), in dim gray, matching the player clock. Handy for confirming sync at a glance or citing a moment.
  • Badges — subscriber, moderator, Prime, bits, and event badges, from the images embedded in the log.
  • Username — in the user’s chosen chat color. Users who never picked one get the same default color Twitch would assign, and colors that would be unreadably dark on the dark background are automatically brightened.
  • The message — with Twitch, BTTV, FFZ, and 7TV emotes shown as images. Animated GIF/WebP emotes animate. “Zero-width” emotes (effects like rain or sparkles designed to sit on top of another emote) overlay their base emote exactly as on Twitch. @mentions are bolded. Everything is real text — you can select and copy it.

How the sync works (from the viewer’s seat)

During playback, messages appear at the bottom at the exact moments they were originally sent — at 2× speed, chat flows at 2× too. When you seek anywhere, the column instantly rebuilds to that point in time, including the previous ~50 messages so you land with context rather than an empty pane. There is nothing to align and no drift to correct, ever: the chat log is indexed by timestamp and rendered directly against the video clock.

Reading back (auto-scroll)

The column normally stays pinned to the newest message, like live Twitch chat. Scroll up to read something you missed and auto-scroll pauses: a pill appears at the bottom — “Chat paused — click to resume” — while new messages keep accumulating quietly underneath. Click the pill (or scroll back down to the bottom) to snap back to live. While you’re reading scrollback the view holds perfectly still; nothing yanks the scroll position out from under you.

To keep the page fast over a six-hour stream, only the most recent couple hundred messages stay in the column (a bit more while you’re reading back). Older ones are dropped from view — seek backward any time to revisit them.

11. Resume & remembered settings

TwitchSync remembers, per browser, using the browser’s local storage (nothing is written to your files):

WhatDetails
Playback position (per VOD)Saved every few seconds while you watch and when you pause or leave. Reopen the VOD — even after a reboot — and it resumes where you left off, with a brief “Resumed at 3:00:15” toast. Positions in the first 10 seconds aren’t saved, and finishing a VOD (or stopping within the last minute) clears its position so next time starts fresh.
Volume & muteWhatever you set last time is applied to every VOD.
Playback speedAlso remembered globally, so your preferred 1.25× sticks.

Note

Positions are keyed by the VOD’s filename. If you rename a VOD pair, its saved position resets. Different browsers (or private windows) each have their own memory.

12. Tips & tricks

  • Chase the spikes. The purple graph over the seek bar is chat messages per minute. Big moments — clutch plays, jump scares, raid arrivals — light up chat. Hover a spike to read its timestamp, click to jump there, and you’ve built yourself a highlight reel with no editor.
  • Hover before you leap. The tooltip previews the timestamp anywhere on the bar, so you can aim a jump precisely before clicking.
  • Click the video to pause, double-click for fullscreen — the muscle memory from every other player works here.
  • Bookmark VODs. Each VOD’s player URL (/?v=…) is stable. Combined with auto-resume, one bookmark drops you exactly where you stopped last night.
  • Speed through downtime. Queue times and loading screens fly by at 2× (L to lunge forward 10 s at a time), then Space and back to Normal when the action starts.
  • Watching on a laptop? Below ~1100 px of window width the chat column narrows automatically so the video keeps most of the room.
  • Reclaim disk space. Once you’re happy with TwitchSync, the old … - CHAT.mp4 renders are dead weight — several GB each that the app never touches.
  • Keep names in sync when renaming. If you tidy up filenames, rename the .mp4 and .json identically or the pair won’t be matched.

13. Troubleshooting

“This site can’t be reached” / nothing loads

The server isn’t running (or is on a different port). Start it with python3 server.py and watch the Terminal output — it prints the exact URL to open. Remember the Terminal window must stay open while you watch.

“error: cannot bind 127.0.0.1:8710 … Try --port”

Another program (possibly an earlier TwitchSync you forgot about) is already using port 8710. Either find that Terminal window and reuse it — the app is already up at the usual URL — or start this one on another port: python3 server.py --port 9000.

A VOD doesn’t appear in the library

  1. Check the pair: is there a chat file whose name matches the .mp4 exactly, aside from the extension? One character off (a stray space, a missing bracket) breaks the match. Extension casing does not matter.
  2. Make sure the video’s filename doesn’t contain  - CHAT — those are treated as chat renders and hidden on purpose.
  3. Confirm both files are inside one of your library folders — open Folders to see the exact paths and per-folder counts.
  4. If the VOD is nested more than four folders deep inside a library folder, add its own folder directly instead.
  5. Reload the library page; it rescans on every visit.

My NAS folder shows “not mounted”

The share isn’t currently mounted, so the folder is skipped (nothing is lost — the entry stays and its VODs return when the share is back). Remount it in Finder with Go → Connect to Server (⌘K), then reload the library. macOS also drops network mounts on sleep or Wi-Fi changes, which is the usual reason a folder that worked yesterday is offline today. If you want it mounted automatically at login, add the share under System Settings → General → Login Items.

“That path doesn’t exist” when adding a folder

Type the path as it appears on this Mac after mounting — for a share that means /Volumes/<ShareName>/…, not an smb:// URL and not the NAS-side path like /volume1/…. Use the volume chips under the input to fill in the mounted part correctly, then type the rest. If you’re unsure, drag the folder from Finder into Terminal to see its exact path.

The video plays but the chat column says “Chat unavailable”

The JSON exists but couldn’t be read or parsed. Usual causes: the file is the compressed .json.gz variant (decompress it, or re-download as plain JSON), the download was interrupted and the file is truncated, or it’s some other chat format renamed to .json. Re-downloading the chat with TwitchDownloader fixes all of these.

Emotes show as text like LUL or widepeepoHappy

The chat JSON was downloaded without embedded images, so there are no emote pictures inside it to draw. Fix it without re-downloading the whole chat: TwitchDownloaderCLI chatupdate -i chat.json -o chat.json --embed-missing — or re-download the chat with “Embed Images” checked. A handful of unknown emotes rendering as text in an otherwise image-rich chat is normal (an emote can vanish from the emote services between the stream and the download).

The video doesn’t auto-play; there’s a big ▶ overlay

That’s the browser’s autoplay policy, typically after opening a bookmarked player URL directly (no click involved). Click the button once and everything proceeds; the policy never interferes when you enter a VOD by clicking it in the library.

After a big seek the video hangs on a spinner for a while

Seeking into an unbuffered region of a 20+ GB file makes the browser fetch fresh data around the target and hunt for the nearest keyframe. On a local disk that’s typically well under a couple of seconds. If it’s persistently slow, check that the VOD file isn’t on a nearly-full or failing drive, and that nothing else is hammering the disk.

Playback stutters at 1.75×–2×

Decoding 1080p60 video faster than real time is CPU-intensive in some browsers. Drop the speed a notch, or close other heavy tabs. (Playback at Normal speed is far lighter than the old two-videos-at-once approach, so if Normal stutters, something else is loading the machine.)

Fullscreen does nothing

Some embedded browser contexts (previews, in-app panes) forbid the fullscreen API. Open the app in a regular browser tab and F will work. Note the browser’s own “full screen window” (⌃⌘F on macOS) is a separate feature and always available.

Keyboard shortcuts don’t respond

The keystrokes are going to the browser UI (address bar, a find bar) instead of the page. Click once anywhere in the player, then try again.

It didn’t resume where I left off

Resume is per-browser and per-filename. It won’t trigger if you stopped in the first 10 seconds or within the last minute (that clears the position on purpose), if you renamed the files since, if you’re in a private window, or if you switched browsers. Clearing the site’s data in browser settings also wipes saved positions, volume, and speed.

Can I check what the server is doing?

The Terminal running server.py logs library requests and any errors. Silence while you watch is normal — video streaming is intentionally not logged.

14. FAQ

Do I still need the … - CHAT.mp4 files?

No. TwitchSync renders chat from the JSON and never opens the chat videos. Keep them if you use them somewhere else; delete them to free several GB per VOD.

Does TwitchSync modify my files?

Never. The server only reads. Watching, seeking, and resuming write nothing to the VOD folder — the only thing stored anywhere is a few bytes of preferences in your browser.

Can I watch from my phone or another computer?

Not out of the box — the server deliberately binds to 127.0.0.1, so only the machine running it can connect. That’s a safety default: your library is never silently exposed to the network.

Does scrubbing around download the whole 24 GB file?

No. The browser requests only the byte ranges it needs around wherever you’re watching. You can hop across a six-hour VOD all evening and read only a fraction of the file.

Why do chat timestamps look like 3:00:15 instead of clock time?

They’re VOD time — hours:minutes:seconds since the stream started — so they line up with the player’s time readout and the seek bar. The moment you see in chat is the number you’d seek to.

How accurate is the sync, really?

Exact, by construction. Each message carries the offset at which it appeared on stream, and the renderer displays every message whose offset has been reached by the video clock. There is no second player to drift and nothing to re-align — the relationship can’t decay over a session.

A few users’ name colors don’t look exactly like I remember from the live stream.

Users who never chose a color get one assigned deterministically (the same scheme Twitch uses), which may differ from the random color you saw live. And genuinely dark chosen colors are brightened slightly so they stay legible on the dark background.

What about the stream title, game, and duration on the library card — where do they come from?

From the chat JSON’s metadata (TwitchDownloader stores the VOD’s title, streamer, game, and length in it). If a chat file lacks them, the card falls back to the filename.

15. Under the hood

For the curious — none of this is needed to use the app.

The server (server.py)

  • Pure Python standard library: a threaded HTTP server bound to 127.0.0.1, with these routes:
    RoutePurpose
    /, /static/…The app itself (HTML/CSS/JS).
    /api/videosRescans every library folder, pairs files, returns the combined listing as JSON.
    /api/foldersLists library folders (plus mounted volumes as suggestions); POST adds or removes one.
    /media?v=…Streams the MP4 with full HTTP Range support (206 Partial Content).
    /chat?v=…Streams the chat JSON with a known length, so the loading bar can show a real percentage.
  • Range requests are the load-bearing feature. TwitchDownloader MP4s keep their index (the moov atom) at the end of the file, so a browser must fetch the tail before it can play anything, and every seek needs bytes from an arbitrary offset. The server implements the full single-range semantics — open-ended, bounded, and suffix ranges, 416 for unsatisfiable requests — and streams in 1 MB chunks.
  • Library metadata without the 90 MB read: the streamer/title/game/length live in the first kilobyte of the chat JSON, so the listing parses just the head of each file (64 KB) and caches the result until the file changes.
  • Safety: the v= parameter is a dictionary key into the scan results — never a filesystem path — with a resolved-path containment check besides; the media folder can’t be escaped. Aborted connections (constant while scrubbing) are swallowed silently instead of spamming tracebacks.

The frontend (static/)

  • Vanilla ES modules, no framework, no build: main.js (routing/lifecycle), library.js (picker), player.js (video, controls, seek bar, fullscreen, shortcuts, resume), chat.js (the chat engine), util.js (helpers).
  • Chat pipeline: download with streamed progress → parse → unpack embedded images into blob URLs (sniffing PNG/GIF/WebP per image) → index every message timestamp into a typed array. Seeks binary-search that index and rebuild the column with ~50 messages of backfill; playback advances a cursor and appends messages in batches on the video’s timeupdate ticks. The DOM stays capped to the most recent ~200 messages (~500 while you read scrollback) so a 20,000-message stream stays smooth.
  • Commit-on-release scrubbing: assigning currentTime aborts in-flight range requests, opens new ones, and forces a keyframe hunt — dozens of those per drag would stutter, so the drag only previews and the seek fires once on release.
  • Emote handling mirrors Twitch semantics: first-party emotes are matched by ID from the message’s fragments, third-party (BTTV/FFZ/7TV) by name against words in the text, and zero-width emotes stack on the previous emote via absolute positioning.
